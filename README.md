# Grand Mobile Support Copilot

Ассистент поддержки для Grand Mobile × Decentrathon 6.0: классифицирует обращения, извлекает сведения и готовит ответ на языке игрока со ссылками на выданные правила. FastAPI + PostgreSQL, React CRM с авторизацией, Telegram-бот и пакетный запуск JSONL. Поддерживает русский, казахский, узбекский, английский, испанский и португальский; восстанавливает казахские буквы из экспорта.

## Запуск

Нужны Docker Compose и архив данных организаторов. Из корня проекта создайте `.env` (существующий файл не перезаписывайте):

```bash
cp -n .env.example .env
```

Основные настройки:

```env
AI_PROVIDER=openai
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=доступная_вам_модель
TELEGRAM_BOT_TOKEN=токен_от_BotFather
AUTO_REPLY_ENABLED=true
```

Модель должна поддерживать Responses API со строгим JSON Schema. Для локального режима без API задайте `AI_PROVIDER=offline`: он показывает резервный эвристический разбор и не отправляет AI-ответы игрокам. Остальные поля можно оставить по умолчанию. Цены неизвестной модели задаются через `MODEL_*_USD_PER_MILLION`; без них стоимость отображается как неизвестная. `TRIAGE_API_KEY` защищает `/triage` отдельным Bearer-ключом и обязателен в production.

Для импорта архива и команд `make` нужен Python 3.13+ с зависимостями:

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.lock
make import-handout HANDOUT=/путь/grand-support-copilot-handout-2026-10-27.tgz

docker compose up -d --build
docker compose exec api python -m app.cli create-staff --login admin --name Admin
```

CRM: [localhost:8080](http://localhost:8080). Пароль администратора задаётся интерактивно, встроенного пароля нет. Восстановление: `docker compose exec api python -m app.cli reset-password --login admin`. Правила из архива доступны движку сразу; `docker compose exec api python -m app.cli seed-rules` добавляет их также в редактор CRM.

Telegram запускается отдельно, через polling; публичный адрес и webhook для него не нужны:

```bash
docker compose --profile telegram up -d --build bot worker
docker compose logs -f bot worker
```

У бота не должно быть активного webhook или второго polling-процесса. Команды: `/start`, `/profile Сервер 01 | Nick_Name`, `/new`, `/tickets`, `/ticket 12`, `/reply 12 текст`, `/language kk`. Фотографию можно отправить с подписью `/reply 12`. Ник — заявленный профиль, владение игровым аккаунтом не подтверждается.

После изменения ключей в `.env` пересоздайте процессы: `docker compose --profile telegram up -d --force-recreate api worker bot`. После изменения кода используйте `docker compose --profile telegram up -d --build`. Данные PostgreSQL сохраняются в Docker volume.

## API и пакетная сдача

```bash
curl http://localhost:8080/triage \
  -H 'Content-Type: application/json' \
  -d '{"kind":"complaint","messages":[{"role":"player","text":"Игрок Arman_Test оскорбляет меня","attachments":0}]}'

make predict IN=tickets.jsonl OUT=pred.jsonl
make evaluate GOLD=private/handout/tickets_valid.jsonl PRED=pred.jsonl
```

Если задан `TRIAGE_API_KEY`, передайте `Authorization: Bearer <ключ>`. Вход: `kind` (`complaint`/`report`) и `messages` с ролями `player`/`reported_player`. Лимит — 40 сообщений и 24 000 символов. Допускаются метаданные экспорта: `ticket_id`, язык, сервер, хеш заявителя, ник обвиняемого, время и количество вложений. Ответ содержит ровно поля контракта:

```json
{"lang":"ru","category":"complaint.insult","priority":"p2","is_spam_or_duplicate":false,"extracted":{"nickname":"Arman_Test","rule_refs":[],"has_evidence":false,"server":null},"draft_reply":{"lang":"ru","text":"Указанные обстоятельства должен проверить сотрудник поддержки.","cited":[]},"needs_human":true,"confidence":0.0,"reasons":["Требуется проверка сотрудником"]}
```

Это пример формы ответа, не результат живой генерации. Есть 14 категорий и приоритеты `p0–p3`. JSONL сохраняет по одному результату на строку плюс `ticket_id`, статус, код ошибки, ссылки на источники и телеметрию. Сообщения администраторов и итоговые метки удаляются до отправки в модель. Без `PERSIST=1` пакетный запуск не требует БД. Коды завершения: 0 — успех, 1 — ошибки строк, 2 — ошибка запуска.

## Как работает и что оценивается

Движок ищет релевантные пункты в локальном корпусе правил (BM25 с расширением запросов RU/KK/UZ), делает один запрос LLM и проверяет категории, язык, ссылки и недопустимые обещания. Номера правил разделены по разделам, например `2.1`, `ЖБ 1.1.2`, `GZ 1.1`. Повторы определяются по заявителю, тексту и метаданным в пределах часа. Простые вопросы и безобидные реплики могут получать автоответ; жалобы, платежи, апелляции, доступ к аккаунту и спорные ситуации требуют сотрудника. Все обращения и результаты сохраняются.

**Фото и другие вложения в CRM проверяет человек.** Они сохраняются как Telegram `file_id`, доступны авторизованному сотруднику; содержимое не передаётся модели. При вложениях CRM сразу готовит передачу сотруднику без вызова LLM и без расхода токенов. В API/JSONL модель может классифицировать сопровождающий текст, но не просматривает изображения. Просьба приложить доказательства необязательна и появляется в конце сбора сведений. Бот не обещает наказание, разбан, возврат или срок решения.

В CRM доступны частоты категорий и приоритетов, языки, доля `needs_human`, стоимость и задержки. Отчёт `make evaluate` сохраняется в `private/evaluation.json` и `.md`; его можно загрузить в админку. Категории оцениваются по Accuracy и macro-F1, приоритеты — по macro-F1; отдельно учитываются валидность ссылок, языки, ручные оценки черновиков и полнота учёта стоимости. Цели задания: ≤ $0.002/обращение и p95 ≤ 5 с.

В выданном `valid` **нет эталонных категорий и приоритетов**, а языковые метки являются подсказками. Без ручной разметки метрики качества остаются пустыми. `make annotation-sample IN=private/handout/tickets_valid.jsonl OUT=private/annotations.pending.jsonl` готовит выборку для разметки. Наличие номера в корпусе не доказывает, что он подходит по смыслу: это требует отдельной оценки. Локальные прогоны и синтетические тесты не являются оценкой качества LLM; реальные качество, стоимость и p95 нужно измерить при доступной квоте.

Квотные ошибки и ошибки проверки сохраняются, обращение передаётся человеку. Временные сетевые сбои повторяются с задержкой; дневная квота и некорректные ответы модели не запускают цепочку повторных платных генераций. Тесты изолированы от внешней сети и не используют API-ключи:

```bash
.venv/bin/pip install -r backend/requirements-dev.txt
PYTHONPATH=backend .venv/bin/pytest -q backend/tests
cd frontend && npm ci && npm run build
```

Архив организаторов, обращения и отчёты с исходными текстами хранятся в игнорируемом Git каталоге `private/`; они не входят в образ. Используйте их только в рамках согласованных организаторами условий. CRM использует сессии, CSRF-защиту, роли и доступ операторов по серверам; проверка фактического владения игровым аккаунтом и независимое хранение вложений пока не реализованы.
