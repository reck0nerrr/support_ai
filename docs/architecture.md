# Support Copilot · технические решения

## Поток данных

Telegram polling или webhook → транзакция PostgreSQL (update ID, игрок, состояние диалога, жалоба, вложения, задание) → отдельный worker → результат разбора → React CRM → утверждение сотрудником → транзакционный outbox → Telegram.

FastAPI не вызывает модель при приёме жалобы. Таблицы `jobs` и `telegram_updates` обеспечивают устойчивость к перезапуску и повторным webhook-событиям. PostgreSQL `FOR UPDATE SKIP LOCKED` позволяет запускать несколько workers. Polling-процесс для одного бота должен быть один. Не запускайте polling одновременно с webhook.

## Границы доверия

- Telegram ID идентифицирует собеседника, а не владельца игрового аккаунта. Ник и сервер вводит игрок. Проверенной привязки пока нет: нужен официальный игровой механизм. Обращения без персонажа видит администратор.
- Сессия сотрудника хранится на сервере; в cookie находится случайный токен, в БД — его SHA-256. Пароли — scrypt с отдельной солью. Выход отзывает сессию. Мутации требуют CSRF-токена; чужой Origin отклоняется.
- Администратор видит все обращения. Оператор и старший модератор — только явно назначенные им серверы. Оператор назначает обращение себе; старший модератор и администратор могут назначать доступного сотрудника.
- Текст игрока, его профиль и документы — данные, а не инструкции для AI. Вложения и произвольные внешние URL модель не открывает. Внутренние комментарии в контекст модели и историю игрока не попадают.
- Черновик никогда не отправляется автоматически. Отправка — явное действие сотрудника с отдельным idempotency key.

## Две версии обращения

`revision` защищает действия сотрудников от конфликтующих обновлений. `content_revision` меняется при новом сообщении игрока или повторном разборе. Назначение ответственного не отменяет уже поставленный AI-разбор. Результат старой версии не заменяет разбор новых сообщений. Старый черновик отмечается как устаревший.

## База знаний

Источник содержит URL, номер пункта, текст, язык, сервер, редакцию и признак утверждения. Редакции добавляются отдельно, текст существующей редакции не переписывается. Перед публикацией новой редакции снимите предыдущую с публикации. Снимки использованных источников сохраняются с каждым разбором.

Начальные три источника — **пересказы справочных статей**, а не полный свод правил и наказаний. Они импортируются неутверждёнными. Поиск MVP — пересечение слов, ограниченное сервером и утверждёнными источниками; это базовый retrieval, без embeddings, морфологии и ранжирующей модели. Его качество нужно измерять на реальных обезличенных жалобах.

В режиме OpenAI используется Responses API со строгой JSON-схемой. Сервер проверяет ссылки по переданным источникам, добавляет канонические URL и не принимает ссылки, придуманные моделью. Без игровых логов `verified_facts` всегда пуст. Проверка корректности интерпретации и цитирования конкретных пунктов остаётся за сотрудником.

В режиме `offline` нет языковой модели: отображаются выдержки исходного обращения и шаблон ответа на русском или английском. Этот режим позволяет проверить инфраструктуру; он не имитирует полноценный AI-анализ.

## Доставка и восстановление

AI-задача повторяется до трёх раз. После окончательной ошибки обращение переходит на ручную проверку. Прерванные AI-задачи возвращаются в очередь через 5 минут; лимит запроса к модели — 90 секунд.

Telegram не поддерживает idempotency key для `sendMessage`. Подтверждённое отклонение хранится как `failed`; сотрудник может запросить повтор. При таймауте чтения, неверном ответе сервера или остановке worker после начала отправки результат — `uncertain`. Такие отправки не повторяются автоматически. Если Telegram принял сообщение, но worker завершился до фиксации результата в БД, доставка тоже будет неопределённой. Сотрудник должен проверить чат перед новым сообщением.

## Вложения

Сейчас БД хранит Telegram `file_id`, MIME, имя и размер. Сотрудник скачивает файл через авторизованный endpoint, который проверяет доступ к жалобе и проксирует загрузку с лимитом 20 МБ. Бот-токен не раскрывается браузеру, файл выдаётся как download с `nosniff`. Ссылки на видео сохраняются в тексте без серверной загрузки.

Независимое архивирование файлов в приватное S3-хранилище, антивирусная проверка, OCR и анализ видео пока не реализованы. Для долговременного архива это следующий этап; текущая загрузка зависит от доступности файла в Telegram.

## До боевого запуска

Нужны официальная проверка профилей, утверждённые правила для нужных серверов и регионов, ключ модели и токен бота. Настройте HTTPS, реальные серверы в доступах сотрудников, сроки хранения и удаление данных, мониторинг, резервное копирование с проверкой восстановления. Docker Compose рассчитан на локальный запуск за loopback; публикация и TLS требуют отдельной конфигурации инфраструктуры.
