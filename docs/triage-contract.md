# Контракт Support Copilot для Decentrathon

Основной POST /triage соответствует контракту из задания Grand Mobile от 27 октября 2026. JSON Schema: [запрос](triage.request.schema.json), [ответ](triage.response.schema.json). Внутри CRM прежние категории сохранены через явный адаптер; в результате анализа дополнительно есть полный объект `triage` с официальной категорией и приоритетом.

## Запрос

```json
{"kind":"complaint","messages":[{"role":"player","text":"Arman_Test оскорбил меня в чате","attachments":2}]}
```

`kind`: complaint или report. `messages`: от 1 до 40 сообщений, суммарно до 24 000 символов. Роли: player и reported_player. Последняя считается спорным утверждением, не фактом и не инструкцией. `attachments` и `images_count` задают количество вложений; содержимое изображений не поступает модели.

Необязательные признаки экспорта: ticket_id, created_at, region, server_lang, lang, reporter_hash, reported_hash, reported_nick, rule_refs_raw, images_count, server. `lang` и `server_lang` — шумные подсказки. `reply_language` — явный выбор языка сотрудником CRM. Поддерживаются ru, kk, uz, en, es, pt, для узбекского сохраняется письменность.

HTTP отвергает неизвестные поля, роли admin, вердикты и эталонные категории/приоритеты. JSONL принимает исторический экспорт и удаляет admin-сообщения, verdict, punishment, violation, status, category и priority ДО построения запроса. Их нельзя использовать как признаки при проверке.

## Ответ

```json
{"lang":"ru","category":"complaint.insult","priority":"p1","is_spam_or_duplicate":false,"extracted":{"nickname":"Arman_Test","rule_refs":[],"has_evidence":true,"server":null},"draft_reply":{"lang":"ru","text":"Здравствуйте! Указанные обстоятельства должен проверить сотрудник. Изображения автоматически не просматривались.","cited":[]},"needs_human":true,"confidence":0.0,"reasons":["Требуется проверка сотрудником"]}
```

Это пример безопасного резервного ответа, не образец содержательного LLM-черновика. HTTP отдаёт ровно поля из контракта. Время, стоимость, статус и безопасный код сбоя доступны в X-Triage-Latency-Ms, X-Triage-Cost-Usd (только если стоимость известна), X-Triage-Status, X-Triage-Error. Полная попытка сохраняется для администратора.

Категории: complaint.insult, complaint.cheat, complaint.dm, complaint.scam, complaint.rmt_ads, complaint.admin, complaint.other, complaint.invalid; report.question, report.help, report.complaint, report.account, report.payment, report.offtopic. Приоритеты p0–p3, критерии берутся из taxonomy.json; платежи/компрометация и реальные угрозы повышаются сервером, жалобы с вложениями получают не ниже p1.

`extracted.rule_refs` — заявленные игроком номера, они могут быть ошибочными. `draft_reply.cited` — только проверенные ссылки на найденные источники. Общие правила цитируются как 2.1, другие разделы — с префиксом: ЖБ 1.1.2, GZ 1.1 и т. п. Префикс устраняет неоднозначность одинаковых номеров; внутренний ключ gm30-2.1 содержит раздел и пункт. `has_evidence` означает наличие вложений по метаданным, не доказанность нарушения. `confidence` — некалиброванная оценка модели, не вероятность истинности обвинения.

Маркеры [пункт] и список cited должны совпадать. Неизвестный пункт, придуманный URL, неподдержанный номер, обещание наказания/возврата/разбана или утверждение о просмотре изображений отклоняются. Существующий пункт не гарантирует смысловую релевантность — нужна ручная оценка.

Платежи, апелляции, взлом, реальные жалобы и действия в игре требуют человека. В задании пример ответа обещает наказание и ссылается на просмотр скриншотов; реализация следует ограничениям, которые это запрещают.

## HTTP и ошибки

```bash
curl http://localhost:8080/triage -H 'Content-Type: application/json' \
  -d '{"kind":"report","messages":[{"role":"player","text":"Сәлем!"}]}'
```

Если задан TRIAGE_API_KEY, добавьте Authorization: Bearer с ключом сервиса. В production ключ обязателен. 200 — выполнен разбор (включая явно помеченный offline-режим), 401 — неверный ключ, 422 — неверный вход, 502 — ошибка провайдера/источников/проверки черновика. При 502 форма ответа сохраняется, needs_human=true; расходы известной генерации сохраняются. Повторных запросов LLM внутри HTTP-вызова нет.

## JSONL

```bash
make predict IN=tickets.jsonl OUT=pred.jsonl
```

UTF-8, возможен BOM; gzip поддерживается для входа. Один результат на строку, в исходном порядке. В выходе поля контракта на верхнем уровне плюс ticket_id, status, error, telemetry, citations, intent, missing. Метаданные нужны для оценки и стоимости; HTTP их не добавляет. Открытая БД не нужна, пока не указан PERSIST=1. Старые синтетические text/intake-записи читаются только как совместимый локальный формат.

0 — все строки обработаны, 1 — есть ошибки строк/модели, 2 — ошибка запуска. Некорректные строки сохраняются с error=invalid_input. Квотный отказ останавливает дальнейшие API-вызовы с provider_quota_exhausted. Временный Retry-After учитывается; если он больше LLM_RETRY_MAX_WAIT_SECONDS (по умолчанию 60), остальные строки получают provider_cooldown без новых вызовов. Результат не притворяется успешным. Паузы pacing учитываются отдельно от обработки.

Повторы определяются по одинаковому нормализованному тексту, заявителю, обвиняемому, серверу и вложениям в пределах часа. В JSONL используются исходные created_at; HTTP использует время приёма и историю PostgreSQL. Без идентификатора заявителя дедупликация между запросами не выполняется. Семантическая дедупликация не заявляется.
